# 软件工程大作业：四人分工方案

## 1. 分工原则与总览

采用一名前端负责人、三名后端开发者的安排。B 承担相对较少的业务代码，同时负责项目集成与交付；C、D 承担较多且尽量相近的业务开发工作。ABCD 为职责标签，暂不绑定具体成员，可根据首轮开发与联调情况调整。

| 成员 | 主要开发职责                                             | 附加职责                                                     |
| ---- | -------------------------------------------------------- | ------------------------------------------------------------ |
| 方培颖(A)    | 全部前端：账号、好友、群管理、聊天、前端消息同步         | 界面规范、前端构建配置、本模块测试与文档                     |
| 朱凌志(B)    | 账号与统一鉴权、个人资料、账号注销入口、置顶与免打扰设置 | 项目协调、接口衔接、CI/CD 与部署集成、跨模块验收组织、交付与文档汇总 |
| 廖哲维(C)    | 好友关系与分组、群创建、成员及角色、公告、邀请审批       | 社交模块权限能力、相关数据库设计、单元测试与文档             |
| 杨济源(D)    | 会话与消息、实时推送、离线同步、历史与回复、未读状态     | 消息协议、可靠性与延迟验证、相关数据库设计、单元测试与文档   |

B 保留可独立验收的后端业务，并承接工程集成工作。公共工作由 B 组织，各模块负责人提供必要实现、测试和文档，避免 B 承担所有公共代码。

## 2. A：全部前端

A 统一负责页面、交互、前端状态和接口接入。账号部分与 B 联调，好友和群管理与 C 联调，聊天和消息同步与 D 联调。

### 2.1 开发任务

| 工作包     | 具体任务                                                     | 完成标准                                       |
| ---------- | ------------------------------------------------------------ | ---------------------------------------------- |
| 账号与资料 | 注册、登录、登出、账号注销；资料展示和编辑；认证信息修改验证；表单校验与错误提示 | 能完成账号全流程，失败时有明确提示             |
| 好友功能   | 用户搜索、资料展示、申请及处理、好友列表、分组、删除、进入私聊 | 申请同意后双方关系正确，页面与后端一致         |
| 群聊管理   | 选择好友建群；群名、成员、角色、历史公告；管理员设置、群主转让、公告发布、移除、邀请审批、退出 | 操作符合角色权限，成员及权限变化及时体现       |
| 聊天界面   | 会话列表、头像、本人消息区分、文本发送及时间、消息操作菜单   | 私聊和群聊均能使用，失败和空数据状态明确       |
| 消息同步   | 登录同步、实时接收、断线重连、缺失消息补拉、去重与排序、发送结果处理 | 刷新、离线登录和断网恢复后无消息遗漏或重复展示 |
| 历史与回复 | 历史分页、时间及群成员筛选、删除记录、回复、回复数量、关联消息定位 | 未加载的目标可获取并定位，不可见时有提示       |
| 会话状态   | 未读计数与已读上报、置顶排序、免打扰交互                     | 状态与后端一致，重新登录后仍有效               |

### 2.2 工程责任与交付物

- 统一布局、颜色、字体、公共组件和交互规范。
- 维护前端构建命令与配置，由 B 接入整体流水线和部署。
- 与 D 共同确定前端同步规则，负责浏览器端实现和必要测试。
- 编写前端模块文档、页面验收步骤和消息状态处理说明。
- 交付全部页面及接口接入、前端消息同步模块、构建配置和本模块文档。

A 的页面数量较多，优先采用统一组件并完成基本功能，再集中完善样式。B/C/D 提前提供接口约定、示例数据和可用接口。

## 3. B：账号与基础设置后端、项目集成与交付

B 的业务范围以账号和相对独立的会话偏好设置为主，代码工作量目标低于 C、D。集成职责包括接口衔接、运行检查和交付组织。

### 3.1 后端开发任务

| 工作包       | 具体任务                                                     | 完成标准                                                     |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 注册与登录   | 注册信息校验、密码安全存储、登录、登出、会话或凭证管理       | 合法用户可登录，非法请求被拒绝，登出按约定使登录状态失效     |
| 统一身份认证 | 为普通接口和实时连接提供统一身份识别、认证失败处理；约定公共错误格式 | C/D 可复用认证能力，不能冒用其他用户身份                     |
| 个人资料     | 查询和修改用户名、头像、邮箱、手机等；修改认证信息前的身份验证 | 服务端执行校验，验证失败不能完成敏感修改                     |
| 账号注销     | 注销入口、确认和账号状态处理；调用 C/D 提供的模块处理能力    | 社交和消息数据按共同约定处理，避免部分完成后留下失效权限     |
| 会话偏好设置 | 用户自己的置顶、免打扰设置及持久化，提供偏好查询能力         | 设置按用户隔离，重新登录后仍有效；C/D 的权限能力限制可操作会话 |

### 3.2 项目集成任务

| 工作             | B 的具体责任                                                 | 其他成员承担的部分                                   |
| ---------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| 接口衔接         | 汇总接口与调用顺序，跟进字段、错误格式、依赖和变更           | 各成员编写并维护自己模块的接口说明和实现             |
| CI/CD 与部署集成 | 接入构建、测试、覆盖率和质量检查；整合部署配置、HTTPS 与实时连接转发 | A 提供前端配置；C/D 提供本模块运行、迁移和测试要求   |
| 测试环境         | 组织准备测试账号、好友、群和消息数据，整理初始化与重置方式   | 各成员提供本模块初始化能力和样例                     |
| 跨模块验收       | 汇总完整流程用例、组织执行、复现问题、跟进修复并回归         | 各成员执行相关用例，修复自己的模块；各自编写单元测试 |
| 阶段交付         | 跟踪进度、汇总交付清单、组织演示彩排和运行检查               | 各成员提供演示步骤、实现说明及已知问题               |
| 文档整合         | 整合需求、API、数据库与运行文档，检查相互一致性              | 每位成员撰写自己的模块内容                           |

### 3.3 交付物

- 账号、资料、认证及会话偏好设置接口。
- 本模块数据库变更、单元测试和接口文档。
- 整合后的流水线与部署配置、运行及故障处理说明。
- 接口总表、跨模块验收用例、问题和回归记录。
- 阶段交付清单、整合后的项目文档。

B 负责检查机制与问题闭环，模块实现质量仍由各负责人承担。常规检查尽量自动执行，避免所有修改都等待 B 手工检查。

## 4. C：好友与群管理后端

C 承担流程和权限分支较多的社交业务，提供统一的好友关系、群成员和角色查询能力。

### 4.1 开发任务

| 工作包             | 具体任务                                                     | 完成标准                                     |
| ------------------ | ------------------------------------------------------------ | -------------------------------------------- |
| 用户搜索与好友申请 | 根据关键词搜索用户、展示允许公开的基本资料、发送及处理申请   | 重复申请、非法对象及重复处理等情况有明确结果 |
| 好友关系           | 同意后建立双向关系、好友列表、删除好友                       | 双方关系更新一致，跨用户访问受限制           |
| 好友分组           | 分组管理、好友所属分组调整                                   | 分组属于当前用户，不影响对方自己的分组       |
| 群聊创建与查询     | 从好友创建群、初始化成员和群主、群基本信息和成员查询；调用 D 的会话初始化能力 | 群与会话初始化一致，失败时不留下不完整数据   |
| 群角色与权限       | 设置管理员、转让群主、群主和管理员移除成员                   | 服务端校验；管理员不能移除群主或其他管理员   |
| 邀请与退出         | 邀请自己的好友、群主或管理员审批、成员退出                   | 未批准者不获得成员权限，退出后权限及时变化   |
| 群公告             | 公告发布和历史公告查询                                       | 发布权限正确，历史信息完整展示               |
| 权限与关联处理     | 为 D 提供成员权限能力；产生社交变更事件；为 B 提供注销时社交数据处理能力 | 权限变化能衔接消息服务，关联数据符合约定     |

### 4.2 工程责任与交付物

- 设计和实现好友、申请、分组、群成员、角色、公告、邀请等数据结构。
- 编写覆盖正常、重复请求、并发处理和权限边界的单元测试。
- 维护社交接口与数据库文档，提供给 B 汇总。
- 与 A 联调页面，与 D 联调群会话初始化和成员权限变化，与 B 联调注销及部署。
- 交付社交业务接口、权限查询能力、业务事件、数据库变更、测试和本模块文档。

## 5. D：消息与会话后端

D 承担消息存储、实时性、同步和可靠性等技术复杂度较高的业务。置顶与免打扰设置的写入由 B 负责，D 在会话查询和相关消息行为中使用这些设置。

### 5.1 开发任务

| 工作包         | 具体任务                                                     | 完成标准                                   |
| -------------- | ------------------------------------------------------------ | ------------------------------------------ |
| 会话基础       | 私聊获取或创建、群聊会话初始化、会话列表和摘要查询           | 不重复创建同一私聊，正确关联成员和用户偏好 |
| 消息存储与发送 | 消息标识、会话内顺序、正文、时间、持久化、重复请求处理       | 成功确认的消息已可靠保存，重试不重复入库   |
| 实时推送       | 接入 B 的身份认证、管理连接、向有权限的在线用户推送消息和业务事件 | 登出、退群、移除后权限按约定及时失效       |
| 离线与断线同步 | 增量拉取、同步游标、缺失补齐、推送与补拉衔接                 | 离线登录和断线恢复后不漏消息、不重复展示   |
| 历史记录       | 分页、按时间和群成员筛选、删除记录                           | 查询权限正确，删除后再次查询结果符合约定   |
| 回复与定位     | 回复关联、回复数量、关联消息定位和必要的上下文查询           | 关联正确，目标未加载或已不可见时结果明确   |
| 已读与未读     | 保存已读位置、计算未读数、必要的状态同步                     | 各用户独立，旧请求不覆盖较新的已读位置     |
| 关联处理       | 为 B 提供账号注销时消息数据处理能力；响应 C 的成员变更       | 历史、推送及查询权限符合共同约定           |

### 5.2 工程责任与交付物

- 与 A 定义消息、事件、请求标识、错误和同步游标格式；B 汇总跨模块接口约定。
- 设计和实现消息、会话、已读及同步相关数据结构。
- 编写正常收发、重复请求、离线、断线、服务重启和越权场景的测试。
- 与 A 配合验证平均消息送达延时不超过课程要求的 200 ms。
- 提供消息模块的运行、迁移和实时连接要求，由 B 整合部署。
- 交付消息接口、推送与同步服务、数据库变更、测试、消息协议及可靠性验证说明。

## 6. 跨模块责任边界

| 交界事项       | 责任划分                                                     |
| -------------- | ------------------------------------------------------------ |
| 登录与实时连接 | B 提供统一认证；A 建立或关闭连接；D 验证连接身份并处理失效   |
| 好友进入私聊   | A 提供入口；C 提供好友关系；D 获取或创建会话并返回聊天数据   |
| 创建群聊       | A 提供界面；C 编排群与成员初始化；D 提供会话初始化能力，双方保证数据一致 |
| 成员与角色权限 | C 维护群成员和角色；D 在发送、查询、推送时执行对应权限检查   |
| 社交事件推送   | C 产生事件；D 提供推送通道；A 更新页面；B 检查完整流程       |
| 置顶与免打扰   | A 提供交互；B 保存用户偏好；D 查询偏好并按约定处理会话排序及消息行为 |
| 账号注销       | B 编排流程和账号状态；C/D 实现各自数据处理能力；A 清理前端状态 |
| 数据库变更     | B/C/D 分别维护本模块表和迁移，跨模块约束共同确认，由 B 汇总  |
| 部署与排障     | B 整合部署并定位问题范围；各负责人修复本模块并提供回归检查   |

开始开发前共同写清以下语义；需求未明确的部分带着具体方案向助教确认：

- 删除聊天记录的范围，以及是否只对本人生效。
- 新成员、退群成员和被移除成员的历史消息权限。
- 群主退出或注销后的群聊处理。
- 好友删除后原私聊及其记录的行为。
- 免打扰下未读计数和提醒的行为；免打扰不应造成消息丢失。
- 回复目标删除后的展示和定位行为。
- 多个浏览器页面同时登录时的连接和状态同步行为。

## 7. 分轮交付

| 轮次   | A                                  | B                                  | C                                | D                                | 整组交付目标                         |
| ------ | ---------------------------------- | ---------------------------------- | -------------------------------- | -------------------------------- | ------------------------------------ |
| 第一轮 | 登录与最小聊天界面                 | 注册登录、鉴权、基础部署和接口约定 | 最小好友关系及权限查询           | 会话、持久化消息、基础推送       | 部署网站上两个账号可以互发消息       |
| 第二轮 | 好友、群创建、会话列表与同步       | 资料接口、置顶免打扰、完整流程验收 | 好友完整流程、建群与基础成员管理 | 群聊、离线补拉、已读与未读       | 好友私聊和多人群聊可用，断线恢复正确 |
| 第三轮 | 群管理、回复、历史、注销等完整页面 | 身份验证、注销编排、跨模块回归     | 角色、审批、公告、退出与注销处理 | 历史筛选删除、回复定位、注销处理 | 覆盖全部基本功能                     |
| 第四轮 | 界面完善、前端回归与文档           | 部署复查、交付彩排、文档整合       | 社交权限与数据一致性回归         | 可靠性、延迟和消息权限回归       | 稳定验收并完成文档和答辩准备         |

轮次表示依赖顺序，可拆成多次课上交付。第一轮就建立部署和测试机制，后续持续检查已交付功能。

## 8. 测试、文档与完成标准

- B/C/D 各自维护后端单元测试，共同保证后端总覆盖率达到 80%；课程从第 6 周开始检查。
- A 负责页面和前端状态检查，各后端成员提供对应异常场景与测试数据。
- B 组织跨模块验收，相关负责人参与执行、修复和回归。
- 每人编写自己的接口、数据或交互文档和演示步骤，B 负责整合。
- 每人准备自己实现的功能逻辑、数据变化、权限和异常处理，供答辩使用。
- 单项任务完成须满足：合并并部署可用、联调通过、必要测试完成、文档更新、本人能解释实现。
- 全员遵守提交、分支和合并请求规范，已交付功能在主分支持续可用。
